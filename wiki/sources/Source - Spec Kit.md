# Source - Spec Kit

## What this source is

Notes defining the Spec Kit framework and Specification-Driven Development (SDD) methodology for AI coding agents and human teams, covering core and optional quality-gate phases and recommended workflows.

## Claims taken from it

- Spec Kit structures software development into five sequential core phases: `/constitution` (principles/constraints), `/specify` (business requirements/what & why), `/plan` (architecture/how), `/tasks` (executable decomposition), and `/implement` (code execution without interpretation).
- Two optional quality-gate phases provide validation: `/clarify` (removes requirement ambiguity before planning) and `/analyze` (read-only cross-artifact review for contradictions and drift before implementation).
- Recommended workflows include a lightweight workflow (`/specify` → `/plan` → `/tasks` → `/implement`) and a full production workflow (`/constitution` → `/specify` → `/clarify` → `/plan` → `/tasks` → `/analyze` → `/implement`).
- Spec Kit's core philosophy is "Intent → Specification → Design → Execution", where each phase produces a structured artifact that serves as reliable context for subsequent phases.
